# Agent 설계 문서

## 실행 흐름

1. 요청 분석: OpenAI LLM이 지역/지역코드, 요청 개수, 조회 기간, 필요한 정보 종류를 구조화한다. 키 미설정 또는 호출 실패 시 기존 규칙 기반 분석으로 대체한다.
2. 계획 수립: 산불위험예보, 산불 이력, 기상 관측 Tool을 필요한 순서로 계획한다. 상세 요청이면 위험예보 후보에서 시군구 코드를 얻은 뒤 상세 Tool을 호출한다.
3. Tool 실행: 공통 응답 구조로 호출하고 각 호출의 시작·종료·결과를 이벤트로 발행한다. 한 Tool의 실패가 다른 Tool을 중단시키지 않는다.
4. 제약 판단: API가 제공한 위험 지수 원자료를 숫자 기준으로 정렬한다. 제공기관이 정의한 등급 기준을 확인하지 못한 상태에서 확률이나 공식 등급으로 바꾸지 않는다.
5. 재계획: 지역 조건 조회가 비거나 실패하면 전국 조회를 한 차례 시도하고 지역을 다시 확인한다. 재계획 상한을 둔다.
6. 최종 응답: 추천 후보, 조회 근거, 실패/자료 부재, 해석상 주의사항을 제공한다.

## 상태 및 Memory

`AgentState`에는 요청, 세션, intent, plan, selected_tools, tool_results, assessment, retry_count, execution_logs 등을 둔다. 대화 Memory는 SQLite의 session_id 단위로 최근 12개 메시지를 저장한다. “같은 조건”, “그 지역” 등 후속 표현이 있는 경우 직전 사용자 요청을 조건 추출에 보조적으로 사용한다. 복잡한 조건 변경이나 다중 턴 추론은 추가 개선 대상이다.

## 이벤트 흐름

메인 Agent는 구독자 구현을 알지 못한 채 `publish()`를 호출한다. 로깅 서브 Agent 역할의 SQLite 저장 콜백이 이벤트를 받아 `execution_logs`에 순서대로 저장한다. 이벤트 수집/저장에는 LLM을 사용하지 않는다. 저장 실패는 메인 Agent의 응답을 중단시키지 않는다.

## 제한 사항

요청 조건 추출에만 선택적으로 LLM을 사용한다. Tool 선택·실행, 지역 필터, 위험 지수 정렬, 제약 검증은 코드가 수행하며 LLM은 산불 위험도나 발생 확률을 생성하지 않는다. LangGraph가 설치되어 있으면 StateGraph를 사용하고, 미설치 개발 환경에서는 동일 노드를 순차 실행하는 fallback을 제공한다. 위험 지수의 정책적 해석과 공식 임계값은 제공기관 문서 확인 전까지 적용하지 않는다.
